# Промт AI-буста: официальный против сводного, и что из этого взять

Дата: 2026-10-25. Опыт: `tools/experiments/boost_prompt_variants.py`,
языковая модель qwen3.8-27b (llama.cpp), по 4 ответа на пару «случай ×
вариант», 84 ответа. Изображения синтетические.

## Вопрос

Сторонняя модель («Sol») предложила свой системный промт для буста
(`tools/experiments/prompts/sol_system_prompt.txt`):

- один сводный промт на генерацию и правку, который сам выбирает режим;
- поле `mode` в ответе;
- шаблон сообщения со строками `<image1> = first attached image`, …;
- правила о прозрачности (RGBA) и о цветных пометках на картинке.

Лучше ли он наших?

## Что у нас было

Системные промты оболочки — официальные файлы QwenLM/Qwen-Image-2.1
(`prompt_rewrite/prompts`), совпадают с репозиторием байт в байт: сверено
по хэшам 2026-10-25. Промт Sol — их пересказ. README того же каталога
прямо говорит:

> Each task has its own checkpoint and its own system prompt … there is no
> merged prompt: the answer contract is part of what each model was trained on.

Режим оболочке известен заранее — по вкладке. Если модель будет угадывать
его сама, появится лишний шанс ошибиться. Пересказ к тому же теряет
правила официального промта правки:

- **Правило (A):** инструкция на китайском — описание тоже на китайском.
- **Правило (B):** язык надписей выбирается по тексту, который уже есть на
  картинке.
- **Без тегов при одном изображении:** Sol ставит `<image1>` и тогда, а
  официальный промт это запрещает.
- **Соотношение сторон** выводится для дорисовки полей, панорам и сеток
  видов; у Sol этого нет.

## Варианты

| вариант | системный промт | сообщение | доставка изображений |
|---|---|---|---|
| `official` | официальный | наше, с тегами модели | после текста, полный размер — как было |
| `sol` | Sol | шаблон Sol | так же |
| `transport` | официальный | наше | **перед текстом, ≤ 1024²** — как в `pe_core.py` |
| `tuned` | официальный + пометки | наше + пометки | как `transport` |

Последние два ряда подсказал официальный код, а не Sol:
`prompt_rewrite/pe_core.py` ставит изображения перед текстом и уменьшает
каждое до 1024² пикселей («matching training»). Оболочка делала иначе:
изображения шли после текста и в полном размере.

## Результаты

| случай | official | sol | transport | tuned |
|---|---|---|---|---|
| генерация «прозрачный фон»: формат RGBA из README модели | **0/4** | 4/4 | — | 4/4 |
| генерация без прозрачности: ложный RGBA | 0/8 | 0/8 | — | 0/8 |
| надписи «Белые ночи», «21 июня» дословно в кавычках | 4/4 | 4/4 | — | 4/4 |
| правка по маске, референс `<image3>` назван верно | **2/4** | **0/4** | 4/4 | 4/4 |
| правка, одно изображение: без тегов | 4/4 | 0/4 | 4/4 | 4/4 |
| аннотация: назван цвет, метка убрана | 2/4 | 4/4 | 3/4 | 4/4 |
| аннотация: JSON и английский | 3/4, 2/4 | 4/4 | 4/4 | 4/4 |
| аннотация, среднее время | 30.1 с | 7.6 с | 11.5 с | 7.8 с |
| правка, одно изображение, среднее время | 18.4 с | 8.4 с | 14.1 с | 13.4 с |

Кроме того:

- **Прозрачность.** С официальным промтом получалось «a completely
  transparent background», а однажды — «checkerboard pattern»: так модель
  нарисовала бы шахматку. Формата из README Qwen-Image-2.1 не было ни в одном
  ответе.
- **Маска.** В режиме «Маска» `<image2>` — сама маска; переписывателю её
  не показывают. Сообщение начинается со строки `Input images: <image1>
  <image3>`, и всё же с изображениями после текста модель в половине ответов
  нумеровала их подряд, и референс становился `<image2>`. Это ошибка рабочей
  оболочки, а не только опыта. Шаблон Sol велит нумеровать подряд и
  ошибается всегда.
- **Аннотация.** Неудачи официального промта: один ответ по-русски, в
  другом рассуждения («### Thinking Process») вместо JSON.

## Решение

Берём официальные промты, а не сводный, и добавляем три вещи:

1. **Доставка как в официальном коде.** Изображения идут перед текстом и
   не крупнее 1024² (`llm/client.py`). Это чинит теги при маске и сокращает
   время правки.
2. **Пометка о прозрачности** для генерации (`boost.T2I_NOTE`): формат RGBA
   из README модели. Мысль взята у Sol, но точная формулировка — из README:
   «The image has alpha channel …», у Sol «an alpha channel». В промт правки
   пометка не попадает: там слово о прозрачности включает альфу даже с
   отрицанием (`2026-09-22-maska-kak-alfa.md`).
3. **Пометка об аннотациях** (`boost.ANNOTATION_NOTE`), только в режиме
   «Аннотация». Тоже идея Sol.

Отклонено:

- **Сводный промт** — см. выше.
- **Поле `mode`** — режим и так известен.
- **Нумерация подряд в шаблоне Sol** — ломает теги при маске.
- **Правило Sol «если среди изображений есть маска, назови её».** Маску
  переписывателю не показывают, а слово о маске в промте правки вредит
  (`mask_protocol.py`).
- **Защита от подмены роли** — промт пишет сам владелец студии.

Проверка рабочего кода на живой модели после внедрения: теги при маске
3/3, RGBA 3/3, аннотация 3/3.

## Что осталось открытым

- **Длина описаний.** Официальный промт T2I требует 400–500 слов, а
  qwen3.8-27b пишет 210–270 при любом варианте промта. Официальная модель
  PE-T2I обучена с размышлением (`enable_thinking`) и `presence_penalty
  1.5`. Оболочка размышление выключает ради скорости. Стоит ли длина
  описания этих секунд, надо мерить по картинкам, а не по тексту.
- **Аннотация.** Убирает ли Qwen-Image саму метку, когда промт об этом
  говорит, на этом опыте не проверялось: он проверял только переписыватель,
  видеокарта не использовалась.
