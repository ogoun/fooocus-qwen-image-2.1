# Кисть маски отставала от руки: своя кисть вместо gr.ImageEditor

Дата: 2026-09-23. Заказчик: «заметил запаздывание при рисовании маски» и
«сделай удобную разметку маской».

## Как искали

Сначала замер синтетикой — и он соврал дважды, прежде чем сказал правду.

1. Движения мыши через Playwright: ровные 16.7 мс кадра, ни одной длинной
   задачи — и на нашем интерфейсе, и на голом Gradio. Но Playwright ждёт
   кадра на каждое движение, то есть шлёт не больше шестидесяти в секунду.
2. События, созданные из JavaScript (`new PointerEvent`), восемь на кадр:
   обработка по 0.05 мс. Контрольный снимок показал, что они **не рисуют
   вовсе** — 0 % холста против 2.17 % у настоящей мыши: редактор принимает
   только доверенные события. Замер мерил пустоту.
3. Протокол отладки браузера тоже ждал кадра и в трёх прогонах из четырёх
   ничего не нарисовал.

Правду сказал исходник. Кисть `gr.ImageEditor` (Gradio 6.5.1, Pixi.js) на
**каждом** движении указателя:

* добавляет кружки нового отрезка в один объект `stroke_graphics`, который
  копит весь мазок с момента нажатия;
* перерисовывает весь накопленный мазок в текстуру размером с изображение,
  умноженное на `devicePixelRatio`.

То есть стоимость движения растёт с длиной мазка. Замер по ходу одного
длинного мазка это подтвердил:

| кадр, плотность 2x | движение по четвертям мазка, мс | рост |
|---|---|---|
| 2048×2048 | 16.7 · 16.7 · 16.7 · 16.7 | 1.0x |
| **3840×2160** | **16.7 · 19.9 · 33.8 · 44.1** | **2.6x** |

С первой четверти мазка бюджет кадра превышен, и чем дольше ведёшь, тем
сильнее кисть отстаёт. Параметрами это не лечится: `fixed_canvas` с меньшим
холстом лишь замедлил бы рост ценой разрешения исходника.

## Что сделано

Своя кисть — компонент `MaskPainter` (`fooocus_qwen/ui/painter/`),
наследник `gr.HTML`. Каждое движение рисует только новый отрезок поверх уже
нарисованного — стоимость постоянна при любой длине мазка и любом размере
кадра. Холст хранится в полном разрешении исходника, на экран выводится
CSS-трансформацией, поэтому масштаб и сдвиг ничего не перерисовывают.

На том же сценарии, что уличил редактор Gradio:

| кадр, плотность 2x | движение по четвертям мазка, мс | рост |
|---|---|---|
| 3840×2160, своя кисть | 16.7 · 16.7 · 16.7 · 16.7 | **1.00x** |

Удобство разметки — то, чего у редактора Gradio не было:

* размер кисти `[` `]` и Shift+колесо, кольцо курсора ровно в размер кисти;
* ластик кнопкой или клавишей E, а правая кнопка мыши стирает всегда;
* отмена и повтор (Ctrl+Z, Ctrl+Y), очистка и инверсия разметки;
* масштаб колесом к точке под курсором, сдвиг пробелом или средней кнопкой,
  «вписать» клавишей F; на крупном масштабе пиксели показываются как есть —
  маску ведут по краю объекта;
* показать или скрыть разметку (H);
* загрузка перетаскиванием, выбором файла и Ctrl+V; картинка на экране
  сразу, передача на сервер идёт следом и рисовать не мешает;
* палитра — только в режиме аннотации, где цвет и есть адрес области; в
  режиме маски пометки одного цвета и полупрозрачные;
* касание и перо: одним пальцем рисуют, двумя — масштаб и сдвиг.

## На чём держится конструкция

Каждое допущение проверено прототипом на Gradio 6.5.1 до того, как на нём
что-то построено:

| допущение | результат |
|---|---|
| холст в теневом DOM переживает перерисовку шаблона | красный пиксель 255 до и после |
| асинхронный `js` у кнопки подменяет значение перед отправкой | подменил |
| значение из Python видно скрипту через светлый DOM | видно |
| `props.value` из скрипта доходит до Python | доходит |
| собственное свойство (язык) обновляется из Python | да — если конструктор принимает его явным параметром |
| загрузка файла из скрипта (`/gradio_api/upload`) | 200, путь на сервере |
| раздача файла из каталога загрузок | 200 |
| чужой файл той же дорогой | **403** |

Последняя строка — граница безопасности, на которой стоит разбор значения:
путь из браузера принимается только внутри каталога загрузок Gradio
(`payload._inside`), иначе поле `source` было бы чтением любого файла с
диска. Проверено тестами, включая попытку выйти через `..`.

Попутно найдено: каталог кэша Gradio по умолчанию — `.gradio/` в рабочем
каталоге, то есть внутри проекта. Свои файлы кисть кладёт в каталог
загрузок (он во временном каталоге системы), а `/.gradio/` добавлен в
`.gitignore`.

## Три дефекта, найденные при проверке

* **Атрибут `hidden` проигрывал собственному `display`**: заставка
  «Загрузка…» висела поверх картинки, палитра была видна в режиме маски.
  Лечится правилом `[hidden] { display: none !important; }`.
* **Кисть сжималась до ширины, выведенной из пропорции**: блок Gradio
  центрируется авто-отступами, и при `aspect-ratio` его ширина считалась от
  высоты — 567 px посреди колонки в 1351. Лечится явной шириной.
* **Сглаженная кайма считалась пометкой**: ластик того же размера оставляет
  по краю мазка бледную кайму, и после стирания маска выглядела непустой.
  Разбор маски получил порог 128 — тот же, что у бинаризации условного
  изображения (`masking.MASK_THRESHOLD`).

## Проверка

`tools/ui_check.py` поднимает интерфейс той же дорогой, что боевой запуск,
с подставным генератором и проходит в браузере всю цепочку: загрузка,
мазок, «Применить» — и сверяет, **в каком месте кадра** маска пришла на
сервер (центр 255, угол 0). Плюс отмена, ластик правой кнопкой, аннотация
со сведением цвета, расширение холста с помеченной новой площадью,
«Отправить в редактор», язык, раскладка на шести размерах окна и тот самый
замер запаздывания. 56 проверок, ноль провалов.
