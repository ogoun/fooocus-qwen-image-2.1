# Fooocus-Qwen-Image-2.1

Оболочка в духе [Fooocus](https://github.com/lllyasviel/Fooocus) поверх
локальной модели [Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1):
одна строка промта, одна кнопка «Сгенерировать», всё остальное — за
переключателем «Продвинутое». От Fooocus взята философия интерфейса и каталог
из 277 стилей; внутренняя машинерия Fooocus (она рассчитана на ограничения
SDXL) не используется — Qwen-Image-2.1 их не имеет.

Возможности: генерация из текста, редактирование изображения промтом, в том
числе по маске (кистью), по цветным аннотациям нескольких областей сразу и по
точно вырезанной области; расширение холста (outpaint); до 10 референсных
изображений с адресацией тегами `<image1>`…`<image10>`; три пресета качества;
подключение внешней языковой модели для AI-буста промта и описания
изображений; галерея истории с восстановлением параметров прямо из PNG;
двуязычный интерфейс (RU/EN).

Подробное руководство — в [`docs/USAGE.md`](docs/USAGE.md). Устройство системы
— в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Требования к оборудованию

- GPU NVIDIA с 24 ГБ видеопамяти или больше (собрано и проверено на RTX 3090,
  24 ГБ).
- 64 ГБ оперативной памяти или больше — под неё уходит закреплённая копия
  текстового энкодера (десятки гигабайт), которая позволяет держать
  трансформер резидентным в видеопамяти и не гонять веса по шине на каждую
  генерацию (см. `docs/ARCHITECTURE.md`, раздел 3). Собрано и проверено на
  машине со 128 ГБ ОЗУ.
- Windows 11 (основная целевая платформа); Linux — через `install.sh`/`run.sh`
  без отдельной проверки на этой сборке.
- Около 35 ГБ свободного места под веса модели. Скачивать заранее не нужно:
  установка сама проверит подкаталог `Qwen-Image-2.1/` и достанет
  недостающее с Hugging Face.

## Установка

Из корня проекта, две команды:

```powershell
.\install.ps1
.\run.ps1
```

`install.ps1` проходит шесть шагов: создаёт `.venv`, ставит
`torch`/`torchvision` с CUDA-индекса PyTorch, затем остальные зависимости,
**скачивает недостающие веса модели** (33 ГБ; если они уже на месте, шаг
занимает секунду), **спрашивает адрес и токен языковой модели** для AI-буста
промтов — от этого можно отказаться, нажав Enter, — и заканчивает
самопроверкой окружения.

`run.ps1` запускает интерфейс на `http://0.0.0.0:7865` — доступен и с других
машин локальной сети — и открывает `http://127.0.0.1:7865` в браузере, когда
сервер готов отдавать страницу (отключается ключом `--no-open-browser`). Подробнее о флагах, установке на Linux/macOS и проверке
готовности без переустановки — в [`docs/USAGE.md`](docs/USAGE.md#1-установка-и-запуск).

## Разработка

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m playwright install chromium
.venv\Scripts\python -m pytest -q          # модульные тесты, без видеокарты
.venv\Scripts\python -m ruff check .       # статическая проверка, правила в ruff.toml
.venv\Scripts\python tools\ui_check.py     # интерфейс в настоящем браузере
```

`tools/ui_check.py` поднимает интерфейс той же дорогой, что боевой запуск,
но с подставным генератором вместо модели, и проходит в браузере раскладку
на шести размерах окна, язык, кисть маски (включая замер запаздывания),
галерею и то, что токен языковой модели не попадает на страницу.
Результаты и настройки при этом пишутся в `.tmp/ui_check/` внутри проекта
(под `.gitignore`); `tmp_path` тестов — в `.tmp/pytest/` (`pytest.ini`).
Проверка с настоящей моделью — `tools/smoke.py` (см. `docs/SMOKE.md`).
