# Пользовательские LoRA для Qwen-Image-2.1 (2026-10-02)

Задача: дать пользователю подключать свои LoRA, как в Fooocus и InvokeAI, и
сделать это правильно именно для Qwen-Image-2.1.

## Как это сделано у других

**Fooocus.** Каталог `models/loras` (можно несколько), пять ячеек
«Enable · файл · Weight» во вкладке Advanced → Models, вес от −2 до 2 с шагом
0.01, кнопка «Refresh All Files». В метаданные пишутся имя, вес и SHA-256
файла (своя схема и схема A1111 — `Lora hashes`). Вес вливается прямо в
веса модели с резервной копией; LoRA, у которой больше 12 ключей не нашли
слоя, считается чужой и **молча** пропускается (печать в консоль).
Источники: `modules/config.py`, `webui.py`, `modules/core.py`,
`modules/meta_parser.py`, `ldm_patched/modules/model_patcher.py`.

**InvokeAI.** LoRA — модели в менеджере моделей: при установке файл
«пробуется» (probe) — для какой базы он, по префиксам ключей. У каждой LoRA
свои вес по умолчанию, пределы и **слова-триггеры** (из соседнего
`<имя>.json`, «activation text»). Применяет свой `LayerPatcher` без peft:
обычно вливает дельту в вес, а для квантованных слоёв — «sidecar»-обёрткой.
Метаданные — модель (ключ, BLAKE3-хеш, имя, база) и вес; повтор параметров
находит модель по хешу. Qwen-Image 2.1 в InvokeAI пока нет: карта ключей
kohya у них — для Qwen-Image 1 (`add_q_proj`, `img_mlp.net.0.proj`).

## Чем 2.1 отличается от Qwen-Image 1

| | Qwen-Image 1 / 2512 / Edit | Qwen-Image-2.1 |
|---|---|---|
| блоки | 60 двухпоточных (MMDiT) | 32 однопоточных, общая `modulation` |
| ширина | 3072 | 4096 |
| слои блока | `attn.to_q/k/v`, `add_q/k/v_proj`, `to_add_out`, `img_mlp.net.*`, `txt_mlp.*`, `img_mod`, `txt_mod` | `attn.to_q/k/v/to_out.0`, SwiGLU `img_mlp.proj/gate_layer/out` |

LoRA от Qwen-Image 1 к 2.1 неприменимы. diffusers при этом не падает: он
подключает совпавшие по имени слои (а при чужой ширине — падает на форме) и
предупреждает о лишних ключах. Поэтому «для этой ли модели» решается по
полному списку слоёв 2.1 **и** по формам (`attn.to_q` есть и у 1, но шириной
3072).

## Форматы, которые встречаются на деле

По заголовкам реальных файлов с Hugging Face:

1. **diffusers/peft** — `transformer.transformer_blocks.N.attn.to_q.lora_A.weight`,
   alpha в метаданных `lora_adapter_metadata` (с префиксом компонента:
   `transformer.lora_alpha`). Pruna, Viggle, SimpleTuner.
2. **DiffSynth/ModelScope** — без префикса, `….lora_A.default.weight`,
   `trigger_word` в метаданных.
3. **ai-toolkit / ComfyUI** — `diffusion_model.…`, вход SwiGLU одним слоем
   `img_mlp.gate_up` (строки `[gate; up]`, как в весах ComfyUI и GGUF).
4. **kohya** — `lora_unet_<слой_с_подчёркиваниями>.lora_down/up` и `.alpha`.
5. Реже: DoRA (`dora_scale`), LoKr/LoHa, полные разности `.diff`.

## Ловушки встроенного загрузчика diffusers

`QwenImage21Pipeline` наследует `QwenImageLoraLoaderMixin`, и его конвертер
написан для Qwen-Image 1:

* **слитый `gate_up` теряется молча**: peft получает целевой модуль
  `gate_up`, которого у 2.1 нет, и MLP-часть LoRA пропадает. Опыт ниже:
  встроенный путь даёт вдвое меньший эффект, чем перевод с разрезкой;
* в именах kohya точки восстанавливаются эвристикой по известным словам —
  `gate_layer` 2.1 становится `gate.layer`, `txt_in_in_layer` и
  `modulation_1` не находятся;
* DoRA грузится как обычная LoRA (магнитуда выброшена с предупреждением),
  LoKr/LoHa и `.diff` роняют конвертер.

Отсюда — свой перевод (`engine/lora.py`): плоское имя kohya сверяется со
списком настоящих слоёв 2.1, `gate_up` режется по строкам `lora_B`
(`lora_A` общий), alpha (ключ `.alpha` или метаданные peft) вкладывается в
`lora_B`, а DoRA, LoKr, LoHa и `.diff` честно отклоняются с причиной.

## Опыт `tools/experiments/lora_user.py` (RTX 3090, INT8 + SageAttention, Turbo 1024²)

Эффект — средняя разница пикселей (0…255) с тем же кадром без LoRA:

| файл | формат | ранг, слоёв | эффект |
|---|---|---|---|
| `prithivMLmods/Qwen-Image-2.1-Natural-Exposure-LoRA` | DiffSynth | 16, 224 | 14.2 |
| `SimpleTuner/Qwen-Image-2.1-LoRA-photo-aesthetics-v2` | peft, только внимание | 32, 128 | 22.6 |
| `PrunaAI/Pruna-Qwen-Image-2.1` (8 шагов) | peft, alpha 128 при ранге 64 | 64, 224 | 34.5 |
| `wesjos/Qwen-Image2.1-ZenlessZoneZero-Lora` | ai-toolkit, `gate_up` | 32, 192 | 42.8 |
| `e-n-v-y/Qwen-Image-2.1-Fix` | ComfyUI + DoRA | — | отклонён: DoRA |

Слитый `gate_up` через встроенный загрузчик diffusers: эффект 20.2 против
42.8 у нашего перевода; целевые модули peft — без единого слоя MLP. На
кадре стиль из LoRA при встроенном пути лишь намечен.

Цена неслитой LoRA (медиана трёх кадров после первого):

| | секунд на кадр |
|---|---|
| без LoRA | 9.76 |
| одна LoRA | 10.43 (+7 %) |
| две LoRA | 10.72 (+10 %) |

Подключение — 1.3–2 с (перестановка трансформера с хоста), один раз на
выбор файла. Выгрузка возвращает кадр бит в бит (разница 0.0 с кадром до
подключения), повтор с тем же сидом — тоже 0.0. В профиле «low» (энкодер по
слоям, трансформер не покидает карту) всё то же: подключение прямо на
карте, эффект на месте, выгрузка точна.

Слияние (`fuse_lora`) сэкономило бы эти 7–10 %, но вес тогда не менялся бы
на лету, слияние в bf16 огрубляет веса, а на GGUF и INT8 `fuse_lora` не
работает вовсе (diffusers #12047, #10492). Неслитые адаптеры — то же решение,
что у Turbo.

**Две дистилляции вместе не складываются.** Pruna (8 шагов) поверх Turbo
даёт зернистый кадр: это ускоряющая LoRA со своими узлами, а не стиль. Для
стилевых LoRA Turbo подходит: ZZZ на Turbo и на LowQuality даёт одинаково
выраженный стиль.

## Что сделано

`engine/lora.py` — библиотека файлов, проверка по заголовку (без чтения
весов), перевод форматов, подключение адаптерами peft с одним общим
`set_adapters` для Turbo и пользовательских LoRA; `ui/lora_slots.py` — пять
ячеек «вкл. · файл · вес» с подсказкой под каждой (ранг, слои, триггеры или
причина отказа); метаданные PNG — имя, вес и AutoV2-отпечаток, строка
`Lora hashes` для Civitai; повтор параметров находит переименованный файл по
отпечатку. Разбор устройства — `docs/ARCHITECTURE.md`, раздел 18.

## Не проверено

* LoRA на трансформере Turbo4 (дистиллят влит в веса GGUF; веса Turbo4 на
  этой машине не скачаны). Код подключает LoRA к тому трансформеру, что
  стоит, — проверено только на основном.
* Цена неслитой LoRA на GGUF и на карте в 8 ГБ.
* Edit-LoRA (Anime_consistency, doodle-in) в генерации без исходника.
