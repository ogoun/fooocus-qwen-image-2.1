# Fooocus-Qwen-Image-2.1

[English](README.md) · **Русский**

Студия в духе [Fooocus](https://github.com/lllyasviel/Fooocus) для локальной
модели [Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1): одна строка
промта, одна кнопка «Сгенерировать», всё остальное — под «Продвинутым».
Генерация из текста, правка по инструкции — кистью маски, цветными
аннотациями или по точной области, — расширение холста и до десяти
референсов. Всё работает на вашей видеокарте — от настольной на 24 ГБ до
ноутбучной на 8 ГБ.

![Изображения, сгенерированные Fooocus-Qwen-Image-2.1](docs/images/showcase.webp)

<sub>Все три картинки — пресет MiddleQuality (1536 px, 28 шагов), обычный промт без доработки; надпись на вывеске нарисована самой моделью.</sub>

## Возможности

- **Генерация из текста**: девять вариантов качества, от черновика за 5 секунд
  до 2K — полная модель на 16, 28 или 40 шагах; официальная быстрая модель
  **Qwen Turbo** на 8 шагах для 1024, 1536 и 2048 px (2K меньше чем за минуту
  на RTX 3090); дистилляты **Turbo** (6 шагов при 1 Мп), **Черновик** (то же на
  768 px) и **Turbo4** (4 шага, самый быстрый на картах 8 ГБ). Семь соотношений сторон, 277 стилей Fooocus, до восьми
  изображений за запуск.
- **Работает на картах от 8 до 24 ГБ**: трансформер в bf16, INT8 или GGUF (от
  13.3 до 2.7 ГиБ видеопамяти), профиль памяти по карте и необязательный
  SageAttention (шаг на 15–25 % быстрее). Установка предлагает то, что
  подходит вашей карте; потом всё меняется в настройках, где у каждого
  варианта написана его цена. Недостающие веса докачиваются с прогрессом.
- **LoRA**, как в Fooocus: пять ячеек «вкл. · файл · вес» на обеих вкладках.
  Файл проверяется до подключения — LoRA для Qwen-Image 1 / 2512 / Edit,
  FLUX или SDXL помечаются, а не молча ничего не делают, — и подключаются все
  ходовые форматы Qwen-Image-2.1, включая слитый `gate_up` ComfyUI и
  ai-toolkit, который теряет встроенный загрузчик diffusers. Слова-триггеры
  показываются, имена, веса и отпечатки LoRA пишутся в PNG.
- **Референсы** — до десяти изображений, в промте каждое адресуется тегом
  `<image1>`…`<image10>`. В любую ячейку можно положить **позу** — из
  библиотеки или распознанную на своём фото — или нарисованный от руки **эскиз**.
- **Картинки любого формата**: HEIC с телефона, RAW камер (DNG, CR2/CR3, NEF,
  ARW, RAF, ORF…), TIFF 16 бит, PSD, JPEG XL, AVIF, EXR, SVG и другие — кладутся
  как есть, на входе переводятся в PNG в sRGB. См. [Форматы картинок](#форматы-картинок).
- **Правка по инструкции** в четырёх режимах области:
  - **Маска** — закрасьте то, что нужно изменить; всё вне маски остаётся побайтово нетронутым.
  - **Аннотация** — обведите несколько областей разными цветами и опишите каждую правку по её цвету в одном промте.
  - **Точная область** — правка кропа вокруг маски в полной детальности с вклейкой обратно.
  - **Без области** — правка всего кадра.
- **Расширение кадра одной кнопкой**: выберите сторону или соотношение
  сторон и нажмите «Расширить» — кадр дорастёт бесшовным продолжением, а
  исходные пиксели вклеятся обратно без изменений. Кадр на месте держит лора
  outpaint; без маски, без второго шага, промт необязателен.
- **Отзывчивая кисть маски**: размер, ластик, отмена и повтор, масштаб, сдвиг, кадрирование без потерь,
  вставка из буфера обмена, сенсорный ввод. Стоимость мазка постоянна —
  никакого запаздывания на кадрах 4K (у стандартного редактора Gradio она
  росла по ходу мазка с 16.7 до 44 мс на движение).
- **AI буст**: внешняя OpenAI-совместимая языковая модель (llama.cpp, vLLM,
  LM Studio) переписывает короткий промт в подробный по официальным
  системным промтам Qwen. Работает и с моделями без зрения.
- **Сохранённые промты** прямо под полем промта на обеих вкладках: выбрать —
  загрузить, ввести имя — сохранить, удалить. В поставке есть **Upscale** —
  промт восстановления для вкладки правки: выше разрешение, исправлены гамма
  и баланс белого, лица остаются в точности такими же.
- **Галерея** с параметрами каждого изображения прямо в PNG: повторить их,
  вернуть картинку в редактор, восстановить параметры из любого PNG.
- **Видео со звуком**: MiniMax H3 через движок
  [FreeVideo](https://github.com/FlashML-org/FreeVideo), от 8 ГБ видеопамяти.
  Режимы:
  - текст → видео;
  - первый кадр → видео;
  - первый и последний кадр;
  - по референсам: до 9 картинок, 3 видео и 3 звуков для персонажей, стиля и
    голоса.

  Ещё есть:
  - длительность в секундах, до минуты;
  - черновик, который доводится до финала без новой генерации;
  - «последний кадр → следующий шот»;
  - **раскадровка**: бриф разбивается на шоты, они снимаются цепочкой и
    склеиваются с переходами.

  Картинка уходит во вкладку одной кнопкой. См. [Видео](#видео).
- **Двуязычный интерфейс** (русский / английский), переключается на ходу.
- **HTTP API** (`--api`): всё, что умеет интерфейс, — генерация, правка,
  расширение кадра, позы, AI буст, галерея, настройки — вызовами JSON с
  очередью задач и прогрессом, под Bearer-токеном. Сам интерфейс можно
  закрыть логином и паролем. См. [docs/API.md](docs/API.md).
- **Рассчитано на одну карту 24 ГБ**: веса сами переезжают между видеопамятью
  и ОЗУ, эмбеддинги промтов кэшируются, VAE декодирует плитками без швов.

## Интерфейс

### Генерация

Введите промт, выберите строку в «Качестве и скорости» и нажмите
«Сгенерировать». Список справа идёт от самого быстрого варианта к лучшему, и
у каждой строки написаны шаги и размер кадра. С
включённым **AI бустом** промт сначала переписывает языковая модель. Кнопка
«Переписать сейчас» показывает переписанный текст до генерации — его можно
проверить и поправить. В модель уходит то, что стоит в поле «Переписанный
промт». Клик по результату (или по заполненной ячейке референса) открывает
его в полном размере: ещё клик — 100 %, перетаскивание — сдвиг, стрелки —
другие результаты, Esc — закрыть. «Отправить в редактор» кладёт выбранный результат в кисть и
открывает вкладку «Редактирование», «Отправить в референсы» кладёт его в
первую свободную ячейку референсов. Обе кнопки есть и под результатом правки.

![Вкладка генерации: референсы слева, результат, список «Качество и скорость» справа, промт внизу](docs/images/generate.webp)

На каждой ячейке референса два маленьких значка в нижних углах. Человечек
открывает библиотеку поз: выбранная поза ложится в ячейку скелетом OpenPose,
и модель ему следует.

![Библиотека поз](docs/images/pose-window.webp)

![Скелет позы в ячейке референса и результат по нему](docs/images/pose-result.webp)

Карандаш открывает холст для эскиза: нарисуйте, нажмите «Принять» — и
набросок становится референсом.

![Окно эскиза](docs/images/sketch-window.webp)

### LoRA

Аккордеон «LoRA» под «Продвинутым»: выберите файл в ячейке и задайте вес.
Строка под ячейкой — ранг, число слоёв и слова-триггеры или причина, по
которой файл не подключится.

![Ячейки LoRA на вкладке генерации](docs/images/loras.webp)

результат стоят рядом.

Откройте «Расширить кадр», выберите соотношение сторон (или стороны и долю) и

### Видео

MiniMax H3 снимает картинку и звук за один проход:
1. выберите режим;
2. опишите сцену на любом языке — **AI буст (формат H3)** перепишет текст в
   структуру, на которой учили H3;
3. задайте длительность и нажмите **«Снять ролик»**.

Под ползунком видно, что получится: `864×480 · 124 кадра · 5.17 с`.

**Черновик** считает только первый проход в половинном размере, а
**«Довести черновик до финала»** заканчивает тот же ролик, без новой
генерации.

Аккордеон **«Раскадровка»**:
- превращает бриф в шоты, их можно править;
- снимает шоты так, что каждый начинается с последнего кадра предыдущего;
- склеивает их встык или наплывом, с выровненной громкостью;
- показывает контактный лист для приёмки.

Кнопка **«В видео»** под результатом генерации и правки отправляет картинку
сюда.

### Галерея

Каждый результат хранит параметры внутри PNG. Выберите картинку, чтобы их
увидеть, и повторите на вкладке генерации или откройте картинку в редакторе.
Двойной клик по миниатюре открывает её в полном размере.

![Галерея с карточкой параметров выбранной картинки](docs/images/gallery.webp)

### Настройки

Адрес языковой модели, системные промты AI буста, **производительность** и
отчёт о видеопамяти. «Точность модели» и «Профиль памяти» — списки, где у
каждого варианта написаны видеопамять и карты, для которых он; подходящая
вашей карте точность помечена, а у «Авто» сказано, чем он станет на ней. Токен доступа
только записывается — страница его никогда не показывает.

![Вкладка настроек](docs/images/settings.webp)

## Требования

| | Минимум | Проверено на |
|---|---|---|
| Видеокарта | NVIDIA, 24 ГБ — профиль «high»; **8 ГБ** — профиль «low» с GGUF | RTX 3090, 24 ГБ; RTX 4060 Laptop, 8 ГБ |
| ОЗУ | 64 ГБ для «high»; 16–24 ГБ для «low» | 128 ГБ; 24 ГБ |
| Диск | ~35 ГБ под веса модели (+13 ГБ для «low») | |
| ОС | Windows 11; Linux — через `install.sh` / `run.sh` (на этой сборке не проверялся) | Windows 11 |
| Python | 3.12 (подойдёт 3.13) | 3.12 |
| Видео (необязательно) | 8 ГБ VRAM, 16 ГБ ОЗУ, драйвер NVIDIA 580+, ~80 ГБ диска под движок FreeVideo | RTX 3090, 24 ГБ |

Требование к ОЗУ для «high» сознательное: закреплённая копия текстового
энкодера в оперативной памяти позволяет держать трансформер на видеокарте
постоянно и не гонять веса по шине на каждую генерацию (см.
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), раздел 3). При нехватке ОЗУ —
ключ `--no-pin-memory`. Карты слабее 20 ГБ получают профиль «low» сами —
см. [«Карты на 6–16 ГБ»](#карты-на-616-гб).

## Какие настройки для моей карты

Установка смотрит на карту и предлагает точность по этой таблице; профиль
памяти остаётся «Авто». Всё меняется потом во вкладке «Настройки».

| Видеопамять | Точность (предложение установки) | Профиль памяти («Авто») | С чего начать |
|---|---|---|---|
| от 20 ГБ | bf16 (INT8 освобождает 6.5 ГиБ под референсы) | high | Qwen Turbo HD, Среднее |
| 12–20 ГБ | INT8 | low | Qwen Turbo, Низкое, Turbo |
| 10–12 ГБ | GGUF Q8_0 | low | Qwen Turbo, Низкое, Turbo |
| 8 ГБ | GGUF Q4_K_M | low | Qwen Turbo, Turbo4, Низкое |
| 6 ГБ (не проверялось) | GGUF Q4_K_S или Q3_K_M | low | Черновик, Turbo |

Проверено на RTX 3090 (24 ГБ) и RTX 4060 Laptop (8 ГБ); строки между ними
выведены из измеренного веса каждого варианта.

## Установка

Windows, из корня проекта:

```powershell
.\install.ps1
.\run.ps1
```

Linux:

```bash
./install.sh
./run.sh
```

Что делает установка:

1. создаёт `.venv` на Python 3.12;
2. ставит `torch`/`torchvision` с CUDA-индекса PyTorch, затем остальное из `requirements.txt`;
3. проверяет, что `torch` действительно собран с CUDA — сторонние пакеты умеют незаметно подменить его CPU-сборкой;
4. **спрашивает о производительности**: точность трансформера — bf16
   (исходная, 13.3 ГиБ видеопамяти), INT8 (6.8 ГиБ, скорость почти та же)
   или вариант GGUF (Q8_0 … Q3_K_M; Q4_K_M — 3.9 ГиБ, для 6–8 ГБ) — и
   ставить ли SageAttention (на 15–25 % быстрее; под Windows — готовая
   сборка и `triton-windows` под ваш torch). Enter — точность, которая
   подходит к найденной видеокарте (на 24 ГБ — bf16, на 8 ГБ — Q4_K_M);
5. **скачивает веса модели** (`Qwen/Qwen-Image-2.1`) в `Qwen-Image-2.1/`:
   ~33 ГБ при bf16; при INT8 bf16-шарды трансформера не качаются, а
   INT8-трансформер (7.3 ГБ, `unsloth/Qwen-Image-2.1-FP8`) ложится в
   `Qwen-Image-2.1-INT8/` — всего ~26 ГБ. Сверяет файлы с индексом модели,
   докачивает оборванное, не трогает то, что уже на месте. При GGUF файл
   варианта (`unsloth/Qwen-Image-2.1-GGUF`) ложится в `Qwen-Image-2.1-GGUF/`.
   На картах слабее 20 ГБ здесь же один раз собирается INT8-копия текстового
   энкодера (`Qwen-Image-2.1-TE-INT8/`, 8.4 ГиБ, около 20 с). Тем же шагом в
   `DWPose/` ложатся веса распознавания позы (DWPose, 350 МБ). Остальное
   качается при первом использовании, со строкой прогресса: адаптер Turbo,
   трансформеры Qwen Turbo и Turbo4 и лора outpaint (159 МБ, `Qwen-Image-2.1-outpaint/`).
   Если выбранной точности нужен пакет, которого нет в окружении (GGUF
   нужен `gguf`), он ставится из `requirements.txt` раньше весов;
6. **спрашивает адрес и токен языковой модели** для AI буста и проверяет связь.
   Enter пропускает шаг: без неё работает всё, кроме AI буста и «Описать изображение»;
7. проверяет окружение.

Полезные команды:

```powershell
.\install.ps1 -Recreate                                  # пересоздать .venv с нуля
.venv\Scripts\python -m fooocus_qwen --selftest          # проверить окружение
.venv\Scripts\python -m fooocus_qwen --fetch-model       # скачать или докачать веса
.venv\Scripts\python -m fooocus_qwen --setup-llm         # заново настроить языковую модель
.venv\Scripts\python -m fooocus_qwen --setup-performance # заново выбрать точность и SageAttention
```

## Запуск

`run.ps1` поднимает сервер на `0.0.0.0:7865` — он доступен и с других машин
вашей сети — и открывает `http://127.0.0.1:7865` в браузере, как только
страницу можно отдать. Модель грузится в фоне, пока вы набираете первый промт
(около 30 секунд).

Аргументы передаются приложению:

```powershell
.\run.ps1 --lang ru --port 7870 --preset LowQuality
```

| Ключ | Значение |
|---|---|
| `--host`, `--port` | адрес прослушивания (по умолчанию `0.0.0.0:7865`) |
| `--lang en\|ru` | язык интерфейса при запуске (по умолчанию `en`; переключается кнопкой EN/RU в любой момент) |
| `--preset LowQuality\|MiddleQuality\|MaxQuality\|Turbo\|TurboDraft\|Turbo4\|QwenTurbo\|QwenTurboHD\|QwenTurbo2K` | пресет качества по умолчанию |
| `--lora-dir ПУТЬ` | каталог файлов LoRA (по умолчанию `loras/`; можно указать каталог LoRA из ComfyUI) |
| `--no-open-browser` | не открывать браузер |
| `--no-preload` | грузить модель при первом обращении, а не при запуске |

### Пресеты качества

Интерфейс называет пресеты по тому, что они дают; в скобках — имена для
`--preset`, сохранённых промтов и параметров в PNG.

| В интерфейсе | Разрешение | Шагов | RTX 3090 | RTX 4060 Laptop 8 ГБ |
|---|---|---|---|---|
| **Черновик** (TurboDraft) | 768 px | 6 | ~5 с | 18.8 с |
| **Turbo** | 1024 px | 6 | ~11 с | 31.9 с |
| **Qwen Turbo** (QwenTurbo) | 1024 px | 8 | 10–13 с | |
| **Turbo4** | 1024 px | 4 | | 19.3 с* |
| **Qwen Turbo HD** (QwenTurboHD) | 1536 px | 8 | ~25 с | |
| **Qwen Turbo 2K** (QwenTurbo2K) | 2048 px | 8 | ~49 с | |
| Низкое (LowQuality) | 1024 px | 16 | ~21 с | 66.5 с |
| Среднее (MiddleQuality) | 1536 px | 28 | ~93 с | 215.4 с |
| Максимальное, 2K (MaxQuality) | 2048 px | 40 | ~283 с | |

<sub>Столбец RTX 3090: bf16 со штатным вниманием; Черновик — INT8 с
SageAttention; строки Qwen Turbo — bf16 с SageAttention (Среднее с
SageAttention — ~77 с). * Turbo4 против Turbo на том же ноутбуке: 19.3 и
28.7 с для промта из кэша.</sub>

**Qwen Turbo, Qwen Turbo HD, Qwen Turbo 2K** работают на
[Qwen-Image-2.1-Turbo](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo) —
официальной быстрой модели от Qwen: 8 шагов, без CFG, своё расписание. В
отличие от лоры Viggle она чиста на любом размере — сетка 8 px на 1536 и
2048 px на уровне полной модели, — так что это быстрый путь к крупному кадру:
HD втрое быстрее «Среднего» (25 с против 77, оба с SageAttention), 2K —
меньше минуты против ~4.7 минуты у «Максимального». От
основной модели у неё отличается только трансформер (энкодер и VAE сверены
потензорно), поэтому при первом выборе качается только он и под вашу
точность: чекпоинт bf16 (13.6 ГБ) на bf16, GGUF того же уровня
([Abiray](https://huggingface.co/Abiray/Qwen-Image-2.1-Turbo-GGUF), 3–7 ГБ)
на GGUF, Q8_0 на INT8 — так что работает и на картах 8 ГБ. Переход на неё и
обратно — подмена трансформера (на 24 ГБ основной ждёт в ОЗУ). Правит,
расширяет кадр и принимает ваши LoRA; промт правки держит слабее полной
модели. Негативный промт и guidance не действуют, как во всех turbo-пресетах.
Подробно — [docs/research/2026-10-10-qwen-turbo.md](docs/research/2026-10-10-qwen-turbo.md).

**Turbo** работает на [Qwen-Image-2.1-viggle-turbo](https://huggingface.co/Viggle/Qwen-Image-2.1-viggle-turbo)
— дистиллированном адаптере LoRA к этой же модели: 6 шагов без CFG вместо
16–40, генерация и правка. Разрешение — 1 мегапиксель, на котором дистиллят
учили: выше он рисует мелкую сетку с шагом 8 пикселей — одинаково на bf16,
INT8 и с SageAttention и в эталонном коде авторов. Так что Turbo — быстрый
пресет на 1 Мп, а не ускоренный MiddleQuality. Адаптер (1.3 ГБ) скачивается при первом
выборе пресета. Негативный промт и guidance в Turbo не действуют. Правку по
маске и прозрачный фон (RGBA) авторы дистиллята не проверяли.

**TurboDraft** — тот же дистиллят на 768 px: примерно в 1.8 раза быстрее
Turbo (5.4 с против 9.8 на RTX 3090 с INT8 и SageAttention), на полном
размере чисто. Им удобно перебирать промты и сиды, а понравившийся кадр
повторить на Turbo или MiddleQuality тем же сидом. (Совет комментатора с
Reddit; 896 px тоже замерены и почти ничего не дают — 8.3 с.)

**Turbo4** — 4-шаговый дистиллят Viggle (предварительная версия v0.1),
влитый в трансформер и сжатый в GGUF Q4_K_M
([Abiray](https://huggingface.co/Abiray/Qwen-Image-2.1-viggle-4-steps-turbo-GGUF)).
Самый быстрый пресет: на RTX 4060 Laptop 19.3 с на кадр против 28.7 у Turbo.
Надписи держит не хуже Turbo, картинка контрастнее; в **правке он слабее** —
кадр уходит от исходника, для правки лучше Turbo. Это отдельный трансформер
(4.2 ГБ, качается при первом выборе), поэтому переход на Turbo4 и обратно —
подмена трансформера: около 4 с на 8 ГБ, на 24 ГБ основной ждёт в ОЗУ.

### Скорость и память: точность и SageAttention

Во вкладке «Настройки», «Точность модели» (чем ниже в списке, тем меньше
видеопамяти и заметнее потеря качества):

- **bf16** — исходные веса, 13.3 ГиБ видеопамяти;
- **INT8** — [INT8-веса Unsloth](https://huggingface.co/unsloth/Qwen-Image-2.1-FP8)
  в режиме «только веса»: 6.8 ГиБ на карте вместо 13.3, примерно на 5 %
  медленнее; LPIPS к bf16 по замеру Unsloth — 0.064. Освобождает память на
  время генерации — там её и не хватает референсам — и для других программ.
  Пока кодируется новый промт, на карте в обоих режимах текстовый энкодер
  (16.3 ГиБ), и этот короткий пик не меняется.

- **GGUF Q8_0 … Q3_K_M** — [веса Unsloth](https://huggingface.co/unsloth/Qwen-Image-2.1-GGUF)
  от 6.6 до 2.7 ГиБ; Q4_K_M (3.9 ГиБ) — выбор для карт на 6–8 ГБ, Q4_K_S —
  запас на случай нехватки, Q3_K_M — крайний, с заметной потерей.

**Точность действует на все пресеты**, а не на одну модель: пресет
выбирает, какой трансформер работает и сколько шагов, точность — в каком
виде держать его веса.

| Точность | Низкое / Среднее / Максимальное, Turbo, Черновик | Qwen Turbo, HD, 2K | Turbo4 |
|---|---|---|---|
| bf16 | основная модель в bf16 | bf16-чекпоинт Qwen | всегда GGUF Q4_K_M |
| INT8 | основная модель в INT8 | GGUF Q8_0 (своего INT8 нет; Q8_0 того же размера и почти без потерь) | всегда GGUF Q4_K_M |
| GGUF Qx | основная модель, тот же вариант | тот же вариант | всегда GGUF Q4_K_M |

Turbo и Черновик — адаптер поверх основной модели, поэтому идут в её
точности. У трансформера Qwen Turbo архитектура основной модели, так что
числа памяти выше верны и для него; энкодер и VAE общие. Чтобы честно
сравнить пресеты, держите одну точность: на bf16 обе стороны работают на
исходных весах.

«Применить точность» докачивает недостающие веса (с прогрессом) и
перезагружает модель. **SageAttention** переключается на лету; галочка
активна, только если пакет установлен (выберите его в `install.ps1`). На RTX
3090 шаг при 1536 px и выше становится быстрее на 15–25 %.

### Форматы картинок

Ячейки референсов, кисть правки и фото для позы принимают не только PNG и
JPEG — файл кладётся как есть, перетаскиванием или выбором:

| Что | Форматы |
|---|---|
| Фото с телефона | **HEIC / HEIF** (iPhone, Android), AVIF |
| RAW камер | DNG, CR2, CR3, CRW, NEF, NRW, ARW, SRF, SR2, RAF, ORF, RW2, PEF, SRW, X3F, 3FR, IIQ и другие форматы LibRaw |
| Редакторы и печать | TIFF (8/16 бит, CMYK), PSD (сведённое изображение), TGA, JPEG 2000, JPEG XL |
| Рендер | EXR, Radiance HDR, PFM — линейный свет, как при экспозиции 0 |
| Веб и значки | PNG, JPEG, WebP, GIF (первый кадр), BMP, ICO (крупнейший размер), ICNS, SVG |
| Прочее | QOI, DDS, PCX, PNM, SGI, Sun Raster, XBM/XPM |

То, что браузер не показывает, сервер переводит в PNG раньше, чем файл
увидит поле (SVG растеризует браузер, 2048 px по длинной стороне); пока идёт
перевод, внизу экрана строка состояния. Поворот по EXIF применяется,
цветовой профиль (Display P3 у фото iPhone, CMYK) переводится в sRGB, 16 бит
и плавающая точка — в 8 бит, прозрачность сохраняется. На файл, который не
картинка, — сообщение, а не тишина. Те же форматы принимает API в base64.
Декодеры: Pillow, `pillow-heif`, `pillow-jxl-plugin`, `rawpy` (LibRaw),
`OpenEXR`, OpenCV — все из `requirements.txt`. `install.ps1` / `install.sh`
их ставят; окружению, собранному раньше и обновлённому через `git pull`,
их нужно доставить один раз:
`.venv\Scripts\python -m pip install -r requirements.txt` (или повторить
установку). До тех пор журнал запуска и `--selftest` называют, каких
пакетов нет, а отказ получают только их форматы.

### Референсы

Референсы — сетка из десяти ячеек слева от результата на вкладке генерации,
два столбца по пять в рост поля результата, по умолчанию пустая. Картинку кладут в ячейку кликом или
перетаскиванием, убирают крестиком в углу; «Очистить референсы» под сеткой
опустошает её целиком.

Заполненная ячейка подписана своим тегом. При двух и более референсах промт
обязан ссылаться на них тегами `<image1>`, `<image2>`, …: «первое фото»
модель не понимает. Тег идёт по порядку **заполненных** ячеек, а не по
номеру ячейки: пустые в модель не уходят, так что ячейки 1, 3 и 7 — это
`<image1>`, `<image2>` и `<image3>`. При ровно одном референсе теги не нужны.

**Позы.** Человечек на ячейке открывает библиотеку поз: 46 поз
[openposes.com](https://openposes.com/) (модель — Эмма Уотсон), за ними —
ваши. Клик по плитке кладёт в ячейку её скелет. Каталог входит в проект
(`resources/poses/catalog/`); `tools\fetch_poses.py` обновляет его с сайта.

Последняя плитка, «Добавить позу», принимает фото человека. Поза
распознаётся на процессоре за доли секунды
([DWPose](https://github.com/IDEA-Research/DWPose); 350 МБ его весов ONNX
качает установка), скелет сразу ложится в ячейку, а поза сохраняется в
`user/outputs/poses/`, рядом с вашими генерациями. Следом Qwen-Image рисует для неё плитку в стиле
каталога (около 25 с на Turbo, если его адаптер уже скачан, иначе — на
LowQuality). Имя позе можно задать в поле над фото, иначе она станет «Моя
поза N».

Под каждой плиткой — имя позы. Карандаш в углу плитки открывает правку:
новое имя, перерисовка обложки Qwen-Image или «Схематичный вид» — скелет
вместо обложки, если та не удалась. «Удалить позу» стирает свою позу с
диска, а позу каталога только скрывает (`user/outputs/poses/meta/hidden.json`). Правки поз каталога хранятся с
вашими данными (`user/outputs/poses/meta/`) поверх каталога, а сам он не
меняется.

**Эскизы.** Карандаш открывает белый холст с кистью вкладки правки: палитра
и выбор любого цвета, непрозрачность кисти, размер, ластик, отмена и повтор,
масштаб. Полупрозрачный мазок ложится ровно, даже поверх самого себя. «Принять» кладёт рисунок в ячейку,
«Отмена» закрывает окно.

Референсы съедают память. «Детальность референсов» в «Продвинутом» задаёт,
к какому разрешению они приводятся; «Авто» выбирает по числу условных
изображений и сообщает об этом в строке состояния. При полной детальности
пять референсов на 1536 px переполняют карту 24 ГБ, и кадр идёт минуты
вместо секунд.

### LoRA

Файлы `*.safetensors` кладутся в `loras/` в корне проекта — или запускайте с
`--lora-dir`, указав готовый каталог (вложенные папки видны как `a/b`). Пять
ячеек «LoRA» на вкладках генерации и правки: галочка, файл, вес от −2 до 2.
Выбор файла сам ставит галочку; «Обновить список» перечитывает каталог.

Подходят только LoRA для **Qwen-Image 2.1**: её трансформер устроен иначе,
чем у Qwen-Image 1 / 2512 / Edit (32 однопоточных блока, ширина 4096,
SwiGLU), поэтому их LoRA отклоняются с пометкой под ячейкой, а строка
состояния называет каждую пропущенную при генерации. Форматы: diffusers/peft
(alpha из метаданных файла), DiffSynth/ModelScope, ComfyUI и ai-toolkit
(слитый `img_mlp.gate_up` режется на `gate_layer` и `proj`), kohya. DoRA,
LoKr, LoHa и полные разности весов не поддерживаются.

LoRA не сливаются с весами, поэтому вес меняется без перезагрузки: одна LoRA
добавляет около 7 % к кадру Turbo на RTX 3090, две — около 10 %; подключение
файла — 1–2 с один раз. Стилевые LoRA работают и с Turbo; ускоряющие (Pruna,
Lightning) поверх Turbo не складываются. Слова-триггеры показываются под
ячейкой, но в промт сами не добавляются. Подробно —
[docs/research/2026-10-02-lora.md](docs/research/2026-10-02-lora.md).

### Правка

Вкладка «Редактирование» меняет изображение по инструкции. Промт обязателен —
это и есть инструкция. Режим области решает, где будет правка:

| Режим | Что рисуете | Что происходит |
|---|---|---|
| **Маска** (по умолчанию) | область правки | меняется только маска; пиксели вне её сохраняются в точности |
| **Аннотация** | несколько областей разными цветами | цвета становятся частью картинки; ссылайтесь на них в промте («красный круг…») |
| **Точная область** | маленькую область на большом кадре | кроп вокруг маски правится в полной детальности и вклеивается обратно |
| **Без области** | ничего | правится весь кадр |

У вкладки правки своя сетка референсов слева от кисти, с теми же позами и
эскизами: «вставь кота с `<image3>` в отмеченную область». Здесь `<image1>` —
правимое изображение; в режимах «Маска» и «Точная область» `<image2>` —
маска, и референсы начинаются с `<image3>` (в остальных режимах — с
`<image2>`). Подписи ячеек следуют за режимом, а если маска осталась пустой,
строка состояния скажет, куда сдвинулись теги.

«Запас маски» и «Растушёвка» в «Продвинутом» расширяют маску и смягчают шов
склейки. Модели маска всегда уходит резкой, чисто чёрно-белой: серый край
она читает как «сделай прозрачным».

### Расширение кадра

Откройте «Расширить кадр», выберите соотношение сторон — кадр дорастёт до
него, оригинал по центру, — или стороны и долю, нажмите **«Расширить»**.
Маску рисовать не нужно, второй кнопки нет: новая площадь заполняется за
один проход.

Как это устроено: картинка ставится на холст, новая площадь заливается
ровным серым, холст целиком подаётся модели исходником правки (маска на
Qwen 2.1 оставляет на шве видимую рамку), а
[лора outpaint от AusBoss](https://huggingface.co/ausboss/Qwen-Image-2.1-Outpaint-LoRA)
(159 МБ, качается при первом расширении) держит кадр на месте, пока серое
закрашивается. Затем оригинал вклеивается обратно в своём разрешении с
растушёвкой 32 px и выравниванием тона. Без лоры модель часто перекомпонует
кадр (сохранённая часть — 19–29 дБ PSNR против 30–40 дБ с лорой, замерено
здесь), и вклейка даёт шов.

Промт необязателен: слова из него добавляются как то, что должно появиться
на новом месте. С «AI бустом» сцену сначала описывает языковая модель — так
продолжение точнее. За раз расширяйте не больше чем на размер кадра в
сторону: дальше может появиться вторая сцена; для большего — «Отправить в
редактор» и расширить ещё раз. Работает на любом пресете, включая Turbo, и
вместе с вашими LoRA. Подробно —
[docs/research/2026-10-02-outpaint.md](docs/research/2026-10-02-outpaint.md).

### Видео

Вкладка «Видео» работает на [FreeVideo](https://github.com/FlashML-org/FreeVideo)
(Apache-2.0) — движке инференса MiniMax H3 для небольших карт. Что он делает
ради памяти:
- хранит веса в int8 ConvRot;
- асинхронно подкачивает блоки из закреплённой памяти;
- считает таблицы AdaLN заранее, вместо 26 ГБ проекций;
- декодирует VAE плитками;
- сэмплирует в два прохода, 8 + 3 шага.

Ему нужно своё окружение Python (torch 2.13). Поэтому он живёт в папке
`FreeVideo/` и работает отдельным процессом, а модель картинок на время
ролика выгружается.

Установить его можно тремя способами:
- шагом 7 установщика;
- командой `python -m fooocus_qwen --setup-video`;
- кнопкой на вкладке.

Если веса H3 уже есть, например в ComfyUI, добавьте
`--video-reuse-models <папка>`. Совпавшие файлы возьмутся жёсткой ссылкой, а
не скачаются заново.

На веса действует MiniMax H3 Community License. Установка принимает её от
вашего имени, поэтому прочитайте лицензию заранее.

Подробности — [docs/USAGE.md](docs/USAGE.md), раздел 14, и
[docs/research/2026-10-19-video-freevideo.md](docs/research/2026-10-19-video-freevideo.md).

### AI буст

Адрес OpenAI-совместимого сервера задаётся при установке или на вкладке
«Настройки». С включённым **AI бустом** промт переписывается перед
генерацией. Если языковая модель не читает изображения, буст правки
переписывает промт по одному тексту и сообщает об этом. Описание получается
по-английски, если инструкция не на китайском. Текст, который должен
появиться на картинке, — в двойных кавычках — сохраняет свой язык.

### Карты на 6–16 ГБ

Это **расширение**: на картах от 20 ГБ всё работает по-прежнему. «Профиль
памяти» во вкладке «Настройки»:

- **Авто** (по умолчанию) — от 20 ГиБ видеопамяти «high», меньше — «low»;
- **High** — трансформер и bf16-энкодер меняются на карте целиком (24 ГБ);
- **Low** — трансформер не покидает карту; текстовый энкодер (сжатый в INT8,
  точность — на уровне bf16) поднимается на карту по одному слою; крупный
  KV-кэш правки и референсов живёт в оперативной памяти; плитка VAE меньше.
  Turbo — тот же дистиллят, облегчённый адаптер (0.63 ГБ).

Рекомендуемая связка для 8 ГБ — GGUF Q4_K_M + «Авто». Начинайте с
LowQuality (1024 px) или Turbo; MiddleQuality (1536 px) работает, но около
четырёх минут на кадр. Закройте приложения, которые держат видеопамять
(браузер с аппаратным ускорением, игры). Если не хватает памяти — Q4_K_S,
затем меньше референсов. Разбор и замеры —
[docs/research/2026-10-02-8-gb.md](docs/research/2026-10-02-8-gb.md).

## Приватность и безопасность

- **Никакой телеметрии.** Генерация локальная, аналитика Gradio и проверка
  версии выключены. Единственные исходящие запросы — к вашему серверу
  языковой модели, и только при AI бусте или «Описать изображение».
- **Токен языковой модели не попадает в браузер.** Интерфейс доступен в
  локальной сети, поэтому на вкладке «Настройки» токен можно только
  записать. В журналы он тоже не попадает.
- **Ваши данные не попадают в репозиторий**: `llm_endpoint.txt` (адрес и
  токен), `user/` (картинки и сохранённые промты), `logs/` и `tmp/` — в
  `.gitignore`.
- **Путям из браузера кисть не доверяет**: принимаются только файлы из
  каталога загрузок Gradio.
- **Доступ закрывается по желанию.** Интерфейс по умолчанию открыт всей
  сети; `--username`/`--password` ставят перед ним вход, API (`--api`)
  требует Bearer-токен (`--api-token`). Оба секрета можно передать
  переменными окружения вместо командной строки, в журнал они не пишутся.
  За пределами локальной сети добавьте HTTPS обратным прокси. Файлы API
  отдаёт только из каталога результатов.

## Разработка

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m playwright install chromium

.venv\Scripts\python -m pytest -q                 # 1300+ модульных тестов, без видеокарты
.venv\Scripts\python -m ruff check .              # статическая проверка, правила в ruff.toml
.venv\Scripts\python tools\ui_check.py            # интерфейс в настоящем браузере, подставной генератор
.venv\Scripts\python tools\smoke.py               # сквозной прогон с настоящей моделью
.venv\Scripts\python tools\docs_screenshots.py --phase showcase   # картинки README с настоящей моделью,
.venv\Scripts\python tools\docs_screenshots.py --phase ui         # затем снимки интерфейса
```

- `tools/ui_check.py` поднимает интерфейс той же дорогой, что `run.ps1`, но с
  подставным генератором вместо модели. В Chromium он проверяет раскладку на
  шести размерах окна, смену языка, место маски в кадре, запаздывание кисти,
  галерею и отсутствие токена на странице.
- `tools/docs_screenshots.py` пересоздаёт все картинки этого README живым
  прогоном; временные файлы — в `tmp/`.
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) объясняет проектные решения,
  `docs/research/` — замеры, на которых они стоят. История изменений —
  [CHANGELOG.md](CHANGELOG.md).
